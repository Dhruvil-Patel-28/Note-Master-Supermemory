# AGENTS.md

## State of the repo

v3 ("general ingestion") — v2's per-document-type code is gone. The deterministic fact layer (`app/memory/facts.py`: transcript/resume parsers + 3b note facts), the chat-side transcript machinery (`_parse_transcript_sections`, `_extract_cgpa`, `_extract_credits`, `transcript_fact_answer`), and the JSON repair kit (`_salvage`, `_salvage_fields`, `_extract_json`) are all **deleted**. Understanding is now supermemory's job; our backend only converts files to clean text and shuttles raw content over. Earlier history: v1 (FTS5 + sqlite-vec + LadybugDB + PIN gate) lives in git history — retired in Phase 4. What ships now:

- **Capture pipeline:** text + doc + voice upload, extraction, rule-based sensitivity classification (`app/ingestion/classify.py`), status queued→processing→indexed/failed, version groups (`document_group_id`, `is_latest`).
- **Extraction is layout-general:** all PDFs (digital AND scanned) go through **Docling** → markdown with real tables (`app/ingestion/ocr.py::docling_extract`, lazy singleton converter, `DOCLING_ENABLED=1` default); images still go through VLM OCR (`qwen2.5vl:3b`, `OCR_ENABLED`-gated); `.txt/.md/.csv/.json/.docx/.xlsx` keep the native extractors. If Docling fails or is disabled, `_legacy_extract_pdf` (pypdf text-layer check → per-page VLM OCR) runs automatically as fallback.
- **Knowledge layer (raw-only):** every capture (all tiers — labels, not barriers) mirrors into supermemory-server as **exactly one raw-content doc** (`nm-{capture_id}-raw` customId) — `app/memory/sync.py` (`sync_capture`/`forget_capture` under a module RLock), `app/memory/client.py` (best-effort httpx client). No fact docs, no `entityContext`. The server's **memory agent** (Groq 70B by default, see below) reads each doc and writes the graph memories.
- **Ask side:** `routes/chat.py` → intent refusal (`app/retrieval/intent.py`) → `_memory_hits()` hybrid search (chunks + graph nodes grouped per capture, `MIN_MEMORY_SIMILARITY = 0.45` floor, top 5 captures × 3 chunks, 14000-char budget, cross-attached-memory junk filter `_filter_memory_results`/`_memory_grounded`) → doc preview (`_find_document`) → `grounded_answer`.
- **Schema-constrained LLM output everywhere:** both `grounded_answer` and the intent classifier pass a JSON schema via Ollama's `format=` parameter — malformed/shape-drifted output is mechanically impossible, which is why the whole salvage/repair layer could be deleted. `_parse_response` only guards semantics (empty answers, junk kinds). All schema properties are `required` (empty string/array allowed) because optional fields are unreliable under constrained decoding on small models.
- **Guardrails unchanged:** injection scrub first (<2 content words ⇒ refusal), intent `code`/`general` ⇒ clean `REFUSAL_ANSWER` (no retrieval, no LLM), `_grounded` token-overlap verification forces honest not-found, bare yes/no carve-out only for user-referenced queries, sensitive retrievals audit-logged (`sensitive_access=1`). Tiers are labels only. The identity-fact layer stays dormant (`SENSITIVE-FACTS (OPT2)` comments in `routes/chat.py`, `tasks.py`, `ingestion/sensitive.py`) — note revival is no longer uncomment-and-go: the deterministic answer branch was removed from `chat()` and `_extract_json` no longer exists (see the comment block).
- `PLAN.md` remains the source of truth for scope — encryption-at-rest remains unbuilt/deferred.

## Non-obvious facts that constrain all code

- **Repo layout:** `backend/` (FastAPI, uv-managed venv) + `frontend/` (Next.js 16, App Router). Run backend with `uv run uvicorn app.main:app --reload` from `backend/`; frontend with `npm run dev` from `frontend/`. Tests: `uv run pytest tests` from `backend/`.
- **Local-first invariant (amended in v3):** OCR, ASR, embeddings, chat answers, and files-on-disk stay on the machine (`OLLAMA_HOST=http://localhost:11434`; uvicorn binds 127.0.0.1; CORS allows only localhost:3000). **The one deliberate exception:** supermemory's memory agent may run on Groq Cloud — when `SUPERMEMORY_PROVIDER=groq`, document text leaves the machine during ingestion only. Queries never hit the cloud (chat/intent stay on the local 3b).
- **Provider switch (`scripts/run-supermemory.sh`):** `SUPERMEMORY_PROVIDER=groq|ollama`, default **groq**. groq sets `OPENAI_BASE_URL=https://api.groq.com/openai/v1`, `OPENAI_MODEL=${SUPERMEMORY_AGENT_MODEL:-llama-3.3-70b-versatile}`; key resolution `$GROQ_API_KEY` → `~/.supermemory/groq-key` → warn + fall back to the ollama profile (hermes3). Free-tier budgets: llama-3.3-70b = 30 RPM / 1K req/day / **100K tokens/day**; gpt-oss-120b doubles tokens/day; llama-3.1-8b-instant = 500K TPD emergency model. **Embeddings are pinned to local Ollama unconditionally** (`SUPERMEMORY_EMBEDDING_BASE_URL=http://localhost:11434/v1`, nomic-embed-text/768) — the binary silently inherits `OPENAI_BASE_URL` for embeddings when that var is unset, which would point them at Groq (no embedding models there). Quota exhaustion symptom: docs stuck `indexing`/agent failures → wait for midnight UTC reset or flip the provider to ollama.
- **Model picks (16GB Mac tier):** chat/answers + intent `llama3.2:3b` (schema-constrained; sub-second); embeddings `nomic-embed-text`; ASR faster-whisper `base` (CPU); image OCR `qwen2.5vl:3b` (`OCR_ENABLED`, default on in prod, off in tests); PDFs Docling (~1GB models, first convert downloads+loads ~60s, then seconds/doc CPU). qwen3 models remain pathologically slow at JSON on this Mac — don't use them. The chat prompt is a **system message** with the question as an isolated user turn (in-query instructions are data, never commands); `"think": false` + temperature 0.1; notes-are-facts rule; typo-reading rule; enumerate-ALL-items rule; few-shot examples still matter even with the grammar.
- **Backend internals:** raw `sqlite3` stdlib; `app/db.py` per-operation connections, schema at startup, `PRAGMA busy_timeout=10000` (never remove — pipeline holds writes across extraction). `captures` carries `original_filename`, `note` (PATCH note-only re-classifies tier instantly, no re-extraction), `sensitivity_tier`, `memory_doc_ids`. `GET /captures/{id}/file` serves the original upload.
- **Config is env-driven at import time:** `NOTE_MASTER_DATA_DIR`, `OLLAMA_MODEL`, `DOCLING_ENABLED`, `OCR_ENABLED`, `MEMORY_*` read when imported — tests set env before importing app. Runtime data lives in `backend/data/` (gitignored).
- **Versioning + cascade:** re-uploads create a new row sharing `document_group_id` (`is_latest` flip; partial unique index enforces one latest — restore must zero siblings *before* setting the target, two UPDATEs). Restore re-syncs memory. **Deleting the latest version re-syncs the promoted sibling** (`delete_capture` picks it post-promote and calls `sync_capture`) — its memory docs were already forgotten at demotion, so without this the group would vanish from memory.
- **Deletion is self-healing:** `forget_capture` deletes stored `memory_doc_ids` first, then **sweeps every doc whose customId starts with `nm-{capture_id}-`** via `/v3/documents/list` (`_sweep_custom_id_docs`). This exists because deletes used to orphan docs two ways: the column empty (sync crashed before writing ids back) or `_delete_with_retry` timing out (90s cap) while the agent was still processing. Orphan cleanup tool: `backend/scripts/purge_orphans.py` (dry-run by default, `--delete`, `--all` for empty-DB reset) — this exact scenario happened: capture 45 was deleted locally while its 10 docs were mid-ingest and all survived until purged.
- **supermemory-server API quirks:** (1) `/v4/search` needs `containerTag` always injected (default-container searches return empty with zero errors). (2) `DELETE /v3/documents/{id}` returns 409 while processing — poll status first (`_delete_with_retry`). (3) Same-customId add upserts atomically — edits replace in place. (4) `/v3/documents/list` powers the forget-sweep and orphan tooling. (5) Ingest async: queued → indexing → done. (6) Deleting a document cascades its attached graph memories (verified: purge dropped docs and their 6 memories together). (7) The wrapper script must export env explicitly — the server deletes `~/.supermemory/env` after first boot.
- **Memory sync races (fixed):** `sync_capture`/`forget_capture` serialize under a module RLock; version bumps forget demoted siblings; high-tier syncs like any other.
- **Test seam:** conftest's autouse `memory_hits` fixture fakes retrieval hermetically (lexical overlap, plural-stemmed; academic keywords always match; similarity hardcoded 0.5; no-overlap query ⇒ nothing). `DOCLING_ENABLED=0` and `OCR_ENABLED=0` in tests — Docling/VLM paths are exercised via stubbed-converter unit tests plus one real-conversion test (`TestDoclingRouting.test_real_docling_conversion`, loads cached models, unmarked). `@memory` e2e bypasses the fake entirely.
- **Testing quirks:** `uv run pytest tests -m "not llm"` = pure logic, <15s; full suite adds real-Ollama inference (retry loops ×3 for small-model flake). `@memory` battery ONLY via `scripts/run-memory-tests.sh` (nm_test container, never user_main). POST /captures serializes before the background task — re-fetch before asserting tier. Tests share one session DB — use unique `document_group_id`s per test or earlier rows shadow yours. Fixture chains: audio via macOS `say -o file.aiff`; scanned PDF via `cupsfilter txt > pdf` (**stdout**) → pymupdf render → `sips -s format pdf png --out scanned.pdf`; qlmanage hangs headless — never use it.
- **Ops scripts (`backend/scripts/`):** `resync_memory.py` (forget+sync all latest captures; `--delay` seconds between captures, default 5 — free-tier safe; idempotent upserts make re-runs across days safe), `purge_orphans.py` (see deletion above), `clean_memories.py` (sweep duplicate/cross-attached graph memories).

## Stack

- **Frontend:** Next.js (responsive web; no native app in v1).
- **Backend:** FastAPI, orchestrating ingestion pipeline + knowledge layer + guardrail layer.
- **Storage:** SQLite (app state) + supermemory-server (knowledge/retrieval: raw-content docs, embeddings, graph memories, semantic search) + files on disk referenced by path. Embeddings always local; memory-agent LLM switchable groq/ollama.
- **ASR:** faster-whisper `base`, CPU, on-demand per voice note.
- **User model:** single-user v1; `users` table kept for future-proofing.
- **Sensitivity tiers (`none`/`moderate`/`high`)** assigned at ingestion by pure rules; labels only — badged + audit-logged, never blocking.
- **Retrieval is semantic over supermemory** with strict RAG grounding, explicit not-found path, similarity floor, and audit logging of sensitive access.
