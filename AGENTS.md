# AGENTS.md

## State of the repo

v4 ("vector-only") — the supermemory knowledge layer is gone. `app/memory/client.py`, the server-side memory agent, graph memories, the provider switch, and `_document_scope_hits` are all **deleted**; retrieval is now purely local **ChromaDB** (`app/retrieval/vector_store.py`) with Ollama embeddings. Earlier history: v3 (raw-only sync into supermemory-server), v2 (deterministic fact layer: transcript/resume parsers + 3b note facts — `_parse_transcript_sections`, `_extract_cgpa`, `_extract_credits`, `transcript_fact_answer`), the JSON repair kit (`_salvage`, `_salvage_fields`, `_extract_json`), and v1 (FTS5 + sqlite-vec + LadybugDB + PIN gate) all live in git history — retired. What ships now:

- **Capture pipeline:** text + doc + voice upload, extraction, rule-based sensitivity classification (`app/ingestion/classify.py`), status queued→processing→indexed/failed, version groups (`document_group_id`, `is_latest`). Upload cap **250MB** (`_MAX_UPLOAD_BYTES` in routes/captures.py, mirrored by the Next proxy's `proxyClientMaxBodySize`); `.epub` supported via Docling (fails the capture with a clear error when Docling is off — there is no non-Docling epub extractor).
- **Extraction is layout-general:** all PDFs (digital AND scanned) go through **Docling** → markdown with real tables (`app/ingestion/ocr.py::docling_extract`, lazy singleton converter, `DOCLING_ENABLED=1` default); images still go through VLM OCR (`qwen2.5vl:3b`, `OCR_ENABLED`-gated); `.txt/.md/.csv/.json/.docx/.xlsx` keep the native extractors. If Docling fails or is disabled, `_legacy_extract_pdf` (pypdf text-layer check → per-page VLM OCR) runs automatically as fallback.
- **Knowledge layer (ChromaDB):** every capture (all tiers — labels, not barriers) is chunked → whitespace-filtered → embedded (local nomic-embed-text/768) → upserted into one persistent `note_master` collection (`app/memory/sync.py` `sync_capture`/`forget_capture` under a module RLock; `app/retrieval/vector_store.py` owns upsert/search/delete). Chunk ids are deterministic (`nm-{capture_id}-chunk-{i}`) and each chunk carries `{capture_id, chunk_index}` metadata. Understanding is the embedder's job — no fact extraction, no graph.
- **Ask side:** `routes/chat.py` → intent refusal (`app/retrieval/intent.py`) → **`build_context()`** (single assembly seam): vector search (`_memory_hits` → `_vector_hits`: embed query → `vector_store.search` k=100 → whitespace filter → per-capture `_slot_sort_key` slotting, `MIN_MEMORY_SIMILARITY = 0.38` floor, top 5 captures × 4 slots — **6 on enumeration questions**, tiny raw chunks <250 chars demoted, 16000-char budget) → sparse-representation pin (`_apply_document_pin`: labeled doc under 800 retrieved chars gets ≤4000 chars of raw content) → doc preview (`_find_document`) → `grounded_answer` (schema-constrained; enumeration questions get an emphasis block + an expected-count retry). Grounding compares plural-stemmed tokens (`_stem`). Retrieval quality is locked by `scripts/run-retrieval-tests.sh` (marker `retrieval`, live store, context-only assertions — model answers are deliberately NOT asserted).
- **Schema-constrained LLM output everywhere:** both `grounded_answer` and the intent classifier pass a JSON schema via Ollama's `format=` parameter — malformed/shape-drifted output is mechanically impossible, which is why the whole salvage/repair layer could be deleted. `_parse_response` only guards semantics (empty answers, junk kinds). All schema properties are `required` (empty string/array allowed) because optional fields are unreliable under constrained decoding on small models.
- **Guardrails unchanged:** injection scrub first (<2 content words ⇒ refusal), intent `code`/`general` ⇒ clean `REFUSAL_ANSWER` (no retrieval, no LLM), `_grounded` token-overlap verification forces honest not-found, bare yes/no carve-out only for user-referenced queries, sensitive retrievals audit-logged (`sensitive_access=1`). Tiers are labels only. The identity-fact layer stays dormant (`SENSITIVE-FACTS (OPT2)` comments in `routes/chat.py`, `tasks.py`, `ingestion/sensitive.py`) — note revival is no longer uncomment-and-go: the deterministic answer branch was removed from `chat()` and `_extract_json` no longer exists (see the comment block).
- `PLAN.md` remains the source of truth for scope — encryption-at-rest remains unbuilt/deferred.

## Non-obvious facts that constrain all code

- **Repo layout:** `backend/` (FastAPI, uv-managed venv) + `frontend/` (Next.js 16, App Router). Run backend with `uv run uvicorn app.main:app --reload` from `backend/`; frontend with `npm run dev` from `frontend/`. Tests: `uv run pytest tests` from `backend/`.
- **Local-first invariant:** OCR, ASR, embeddings, chat answers, vector store, and files-on-disk all stay on the machine (`OLLAMA_HOST=http://localhost:11434`; uvicorn binds 127.0.0.1; CORS allows only localhost:3000). No cloud LLM anywhere — ingestion and queries never leave the machine.
- **Model picks (16GB Mac tier):** chat/answers + intent `llama3.2:3b` (schema-constrained; sub-second); embeddings `nomic-embed-text` (768-dim, local Ollama); ASR faster-whisper `base` (CPU); image OCR `qwen2.5vl:3b` (`OCR_ENABLED`, default on in prod, off in tests); PDFs Docling (~1GB models, first convert downloads+loads ~60s, then seconds/doc CPU). qwen3 models remain pathologically slow at JSON on this Mac — don't use them. The chat prompt is a **system message** with the question as an isolated user turn (in-query instructions are data, never commands); `"think": false` + temperature 0.1; notes-are-facts rule; typo-reading rule; enumerate-ALL-items rule; few-shot examples still matter even with the grammar.
- **Backend internals:** raw `sqlite3` stdlib; `app/db.py` per-operation connections, schema at startup, `PRAGMA busy_timeout=10000` (never remove — pipeline holds writes across extraction). `captures` carries `original_filename`, `note` (PATCH note-only re-classifies tier instantly, no re-extraction), `sensitivity_tier`. `GET /captures/{id}/file` serves the original upload.
- **Config is env-driven at import time:** `NOTE_MASTER_DATA_DIR`, `OLLAMA_MODEL`, `DOCLING_ENABLED`, `OCR_ENABLED`, `MEMORY_ENABLED`, `CHROMA_PERSIST_DIR` read when imported — tests set env before importing app. Runtime data lives in `backend/data/` (gitignored).
- **Versioning + cascade:** re-uploads create a new row sharing `document_group_id` (`is_latest` flip; partial unique index enforces one latest — restore must zero siblings *before* setting the target, two UPDATEs). Restore re-syncs the vector store. `sync_capture` forgets demoted siblings *before* indexing the new latest, so the store holds exactly one version per group. **Deleting the latest version re-syncs the promoted sibling** (`delete_capture` picks it post-promote and calls `sync_capture`) — its chunks were already deleted at demotion, so without this the group would vanish from retrieval.
- **Deletion is self-healing:** `forget_capture` deletes by metadata `where={"capture_id": ...}` — deterministic ids make `col.delete(ids=[...])` redundant. Deletes are best-effort (embedder/store down = skipped, never fatal to the capture). Orphan cleanup tool: `backend/scripts/purge_orphans.py` (dry-run by default, `--delete`, `--all` for empty-store reset) — ownership is checked against `captures` ids, so chunks from wiped/reset DBs can be swept. Deterministic ids also make `resync_memory.py` idempotent (upsert replaces in place).
- **ChromaDB quirks:** one persistent collection `note_master`, `hnsw:space=cosine`, `embedding_function=None` (we pass pre-computed embeddings). `search` converts cosine distance → similarity (`1 - dist`). `ids`/`documents`/`embeddings`/`metadatas` are positional arrays of equal length. `count()` can be 0 before first ingest — guard `n_results` (`min(k, count())`). `mnemonic: ` hnsw needs at least a few vectors; warm the collection before asserting. `reset()` deletes the collection and nulls the module singleton (`_collection`/`_client`) — re-get on next use.
- **Memory sync races (fixed):** `sync_capture`/`forget_capture` serialize under a module RLock (RLock because sync calls forget internally); version bumps forget demoted siblings; high-tier syncs like any other.
- **Test seam:** conftest's autouse `memory_hits` fixture fakes retrieval hermetically (`MEMORY_ENABLED=0`; fakes `ctx._memory_hits` with lexical overlap, plural-stemmed; academic keywords always match; similarity hardcoded 0.5; no-overlap query ⇒ nothing). `DOCLING_ENABLED=0` and `OCR_ENABLED=0` in tests — Docling/VLM paths are exercised via stubbed-converter unit tests plus one real-conversion test (`TestDoclingRouting.test_real_docling_conversion`, loads cached models, unmarked). `@memory` e2e bypasses the fake entirely.
- **Testing quirks:** `uv run pytest tests -m "not llm"` = pure logic, <15s; full suite adds real-Ollama inference (retry loops ×3 for small-model flake). `@memory` battery ONLY via `scripts/run-memory-tests.sh` (live local ChromaDB + Ollama, `MEMORY_ENABLED=1` — never against the hermetic env). `@retrieval` battery ONLY via `scripts/run-retrieval-tests.sh` (real store + real captures DB). POST /captures serializes before the background task — re-fetch before asserting tier. Tests share one session DB — use unique `document_group_id`s per test or earlier rows shadow yours. Fixture chains: audio via macOS `say -o file.aiff`; scanned PDF via `cupsfilter txt > pdf` (**stdout**) → pymupdf render → `sips -s format pdf png --out scanned.pdf`; qlmanage hangs headless — never use it.
- **Ops scripts (`backend/scripts/`):** `resync_memory.py` (forget+sync all latest captures; `--delay` seconds between captures, default 5; idempotent — deterministic upserts make re-runs safe), `purge_orphans.py` (see deletion above), `requeue_stuck.py` (re-run captures stuck in queued/processing).

## Stack

- **Frontend:** Next.js (responsive web; no native app in v1).
- **Backend:** FastAPI, orchestrating ingestion pipeline + knowledge layer + guardrail layer.
- **Storage:** SQLite (app state) + local ChromaDB persistent vector store (knowledge/retrieval) + files on disk referenced by path. Embeddings always local.
- **ASR:** faster-whisper `base`, CPU, on-demand per voice note.
- **User model:** single-user v1; `users` table kept for future-proofing.
- **Sensitivity tiers (`none`/`moderate`/`high`)** assigned at ingestion by pure rules; labels only — badged + audit-logged, never blocking.
- **Retrieval is semantic over local ChromaDB** with strict RAG grounding, explicit not-found path, similarity floor, and audit logging of sensitive access.
